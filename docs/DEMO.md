# 演示与验收路径

本页区分两条路径：内置离线演示用于快速了解界面和协议；真实模型闭环用于验证用户自己配置的模型、Skill 和数据集。两者的运行结果不能混用。

## 1. 内置离线演示（`demo_scripted` / `heuristic`）

以下命令会安装依赖、重置本地演示数据并启动服务。`--reset` 只适用于可清空的演示库。

```bash
./start.sh --reset
# 或分步执行：
bash scripts/setup.sh
.venv/bin/python -m app.seed --reset --with-optimize
./run.sh                         # http://127.0.0.1:8765
```

Windows 10/11 可执行 `start.bat --reset`。示例数据由确定性适配器提供：

- `demo_scripted`：固定脚本响应，用于离线演示和自动化测试；
- `heuristic`：未配置优化模型时的固定规则修复模式。

这条路径不证明真实模型效果，也不证明真实业务工具或图片服务效果。`seed --with-optimize` 不会替用户配置真实模型，也不会自动完成独立候选验收；不要把 seed 生成的演示项目当作下文真实项目的复制品。

## 2. 界面走查（当前 UI）

1. 打开项目列表，进入项目概览；先核对「配置完整性」和当前版本指针，再打开「最近运行」。
2. 从「Prompt 与模型」（页面内部仍称执行环境）查看业务模型、优化模型、评分模型和 Prompt。已发布配置为只读，修改必须创建草稿并发布新版本；凭据只显示脱敏摘要。
3. 在「优化 Skill」运行详情中，先看「结果概览」的 R（路由）、A（工具参数）、J（联合通过）和下一步，再看「案例对比」的失败原因。
4. 打开案例详情，核对预期、基线、候选三列及工具参数；模型正文和协议事件在「运行记录」按需展开。
5. 候选日常重跑后另行点击「独立验收」；只有验收结论满足接受条件时才点击「应用候选」。应用后回到版本记录确认当前指针已切换，旧版本仍可回滚。
6. 「数据集」页的试跑只验证单个案例，不写入正式指标；最终留出通过单独的 final_test API 运行，建议在候选应用后作为阶段检查；它不强制前置验收，但不得进入优化输入或候选选择。

旧截图仍可帮助定位页面，但截图和旧运行不是当前环境的实时证明。需要真实模型时，请按 [REAL_MODEL_WALKTHROUGH.md](REAL_MODEL_WALKTHROUGH.md) 重新配置、运行和核对。

## 3. 真实模型闭环的最小顺序

真实闭环固定为：冻结数据和初始 Skill → 基线（24 条优化集）→ 优化（仅看 24 条优化集）→ 候选重跑 → 独立验证（12 条、基线/候选各 3 次）→ 应用 → 最终留出（6 条）。首次运行前已声明两个预设缺陷：`进行中 → active` 和 `紧急 → urgent`；正确值分别是 `in_progress`、`high`。本次历史记录使用 24/12/6 划分；教程数据与 Skill 初始/优化后样例见 [examples/task-collaboration](examples/task-collaboration/)。教程资产是合成数据，可直接跟跑但不保证相同分数；`business-contract.md` 仅供数据设计/人工审查，不作为执行模型输入。

业务 Prompt、业务模型、优化模型和评分模型都必须由使用者自行配置；页面入口为「Prompt 与模型」，后端仍称执行环境。真实闭环的评分配置中，`description` 使用语义评分；路由、动作、工具名、字段结构、ID、`status`、`priority` 等使用严格确定性比较。建议评分模型与被评业务模型分开；本次历史记录恰好使用同型号 `deepseek-flash`，因此不能视作独立模型复核。

本次历史结果（仅为本机历史记录，ID 和本地 URL 不可跨环境复用）：

| 阶段 | 结果 | 说明 |
| --- | --- | --- |
| 基线 | 16/24，J=66.7%；路由 20/20，参数 12/20 | 初始 Skill 含两个预先声明的枚举映射缺陷 |
| 优化后日常重跑 | 24/24，J=100%；参数 20/20 | 真实优化模型提出 2 个文件、2 处规则映射修改 |
| 独立验证 | 基线 24/36，候选 36/36 | 12 个不同案例，配对重复 3 次，`accept-v1` 通过 |
| 最终留出 | 6/6 | 不参与优化或候选选择 |

执行、优化和语义评分共使用 369 次真实 `deepseek-flash` API 请求，所有阶段无 fallback、基础设施错误或 `fixture_miss`。业务工具是固定模拟返回，不是外部任务系统。优化器的自然语言摘要曾把 8 条失败写成 7 条；应以结构化统计和案例 ID 为准。

上述数字来自 `output/real-task-loop/` 的本地历史产物，不表示 seed 会创建同一项目，也不表示复制仓库后原项目链接仍有效。重新运行必须使用自己的模型配置、凭据、项目 ID 和运行 ID。

## 4. 不用浏览器的检查

服务启动后可以查看当前环境的项目和运行；示例中的 ID 只在当前本地数据库有效：

```bash
curl -s http://127.0.0.1:8765/api/v3/projects | python3 -m json.tool | head -40
RID="<当前环境中的 run id>"
curl -s "http://127.0.0.1:8765/api/v3/runs/$RID" | python3 -m json.tool
curl -N "http://127.0.0.1:8765/api/v3/runs/$RID/events"
curl -s -OJ "http://127.0.0.1:8765/api/v3/runs/$RID/report.json"
```

## 5. 保留与结束

日常演示结束后保留项目和版本证据即可；需要停止前台服务时在启动终端按 Ctrl+C。只有明确使用可清空的演示数据目录时才使用 --reset；完整备份及恢复见[部署指南](DEPLOYMENT.md)。
