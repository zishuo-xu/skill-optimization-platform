# 日常测试、独立验收与版本隔离

本页定义当前运行模式和隔离规则。页面操作见[使用指南](USER_GUIDE.md)，数据字段见[输入规范](INPUTS.md)，端点见 [API](API.md)。

## 运行模式

| 模式 | 使用的数据 | 作用 | 正常完成后 |
| --- | --- | --- | --- |
| evaluate | 日常测试集 optimize | 普通评测，不调用优化器 | 结果可作为条件一致时的基线来源 |
| baseline | 日常测试集 optimize | 显式建立基线，不调用优化器 | 保存基线结果 |
| optimize | 日常测试集 optimize | 获取/复用基线、分析失败、生成候选、候选重跑 | 候选待独立验收，不产生 accept |
| validate | 独立验收集 validation | 携带 source_run_id，配对比较原始基线与来源候选 | accept / reject / inconclusive |
| final_test | 最终测试集 final_test | 额外阶段留出检查 | 单独评测结果，不参与候选选择 |

日常评测、基线与优化不要求 validation 或 final_test。没有失败证据、未生成有效补丁等情况下，optimize 可用 inconclusive 结束；成功重跑候选的 optimize 则 decision=null，表示待验收。

正式验收默认每案例两版本各重复 3 次；accept-v1 要求至少 3 次完整配对证据，并满足 R/A 不降且至少一项提高、J 不降、关键案例无回归、无基础设施或包完整性错误。数据为空或核心指标无法评估不能算满分。规则详见[评分](SCORING.md)。

## 导入用途

界面默认“日常测试集”，会统一设置 optimize；选择“独立验收集”会统一设置 validation，覆盖文件中原来的日常/验收 split。选择“保留文件划分”才保留显式用途，未指定用途的按配置比例及 group 划分。含 final_test 的文件要求保留文件划分，不能把最终留出转换到优化。

API 省略 import_purpose 按保留文件划分处理，和页面默认不同；自动化调用应显式传递用途。内部 optimize 是“日常测试集”的字段名，不要求另维护一套名字叫“优化集”的数据。

## 候选链与基线

首次优化使用项目当前 Skill；用户基于候选继续优化时，下一轮以该候选为起点，保留来源运行及父版本。正式验收对照的是来源链最初的 root 基线与选定候选，避免只比较最后一步而掩盖累计退步。

来源校验要求项目当前 Skill、环境仍与来源约束匹配，候选来源、静态检查与包完整性有效。版本变化后应重新核对并建立兼容运行，不能把不同环境的结果直接当作配对提升。

基线缓存只有 Skill、环境、数据、评分器与重复次数等指纹一致且结果完整时才复用。新发布数据或评分规则不会改写历史成绩，新运行使用新快照。

## 数据隔离

- 业务执行模型接收 query、context、Prompt、Skill 和执行时工具返回，不接收 expected 或评分标签。
- 优化模型接收日常集失败证据（含 expected/actual/诊断）、少量通过样例、Prompt 与可编辑 Skill；独立验收和最终留出不进入优化上下文。
- 可在日常优化后补充独立验收数据。validate 冻结当前验收数据版本，检查验收案例是否与来源链涉及的日常/最终数据在 ID、归一化 query 或 group 上重复。
- 这些检查不能证明两个不同表述在语义上完全独立；验收样本仍须人工独立准备。看过验收答案后再调规则，就不能继续声称该集合从未用于调试。

验收本身只评分，不生成新候选。最终留出用于额外报告，不充当优化反馈或候选选择依据。

## 应用保护

只有正式验收达标的候选可以通过应用入口成为当前版本。应用检查包完整性、验收来源及 expected_current_version，在同一事务中比较并切换指针；冲突返回 409，不覆盖并发改动。应用仅改变平台指针，不部署外部服务。

已发布 Skill、环境和数据按版本保留。历史运行继续引用原快照；恢复应用前版本也不会删除后续运行证据。
