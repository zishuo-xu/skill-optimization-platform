# 渐进式加载与模型循环的执行约束

平台围绕 Prompt、Skill 和测试集执行、评价、优化、重跑，以提高最终业务工具选择和参数生成的准确率。执行约束必须让模型实际看到加载内容后再决策，不能仅凭事件显示顺序认定技能已经参与推理。

## 本次改动

1. 原生工具批次包含首次加载的 Skill 文件时，加载正文并回填；同批次的业务调用和 finish 返回未执行提示。模型必须在后续轮次重新生成调用。检查覆盖业务调用出现在加载调用之前的情况；每个工具调用均有对应返回，未执行的调用不消耗 fixture、不计入已执行业务结果。
2. 文本协议首次选择子技能时真正读取正文，以文本消息回填，并明确要求下一轮再输出工具调用或结束。已在上下文中提供的缓存及预加载正文无需额外等待。
3. 每次请求模型前检查现有字符预算，覆盖追加的技能正文、工具结果和模型工具调用参数。运行中超限明确报告 context_overflow；不截断历史或破坏调用与返回的配对关系。
4. 更新基线执行策略指纹，防止优化流程复用旧执行语义下的基线。

没有增加工具配置或新的用户设置。业务工具名称、参数说明仍来自 Skill，原生调用继续通过固定 call_tool 入口执行 fixture 模拟。初始加载继续使用已有溢出策略；运行中不通过删除历史自动恢复。

## 验证边界

回归用例验证模型请求中正文可见、首次加载批次不执行业务调用、缓存命中不额外增加轮次、文本消息协议合法、上下文超限时不再请求模型，以及旧基线指纹失效。

这些检查验证加载和后续调用之间存在新的模型推理机会，不能证明模型内部确实使用了正文。Skill 的效果仍需由工具选择、参数正确性和独立验收集结果判断。真实业务服务不在本次验证范围内。
