# 案例过程的业务视图

案例详情和单案例试跑把执行链路收束为两个用户真正需要判断的步骤：

1. **加载子技能**：`skill_selected` 表示模型选择了技能，`skill_read` 才表示正文确实已加载。只有收到读取事件才显示“已加载”；选择后没有读取证据时显示待确认，执行结束仍没有读取证据则显示无法确认。相同路径的自动加载与缓存读取合并成一个技能步骤，缓存状态保留在详情中。
2. **调用业务工具**：业务工具的开始、完成、返回和 fixture 错误合并为一次调用。相同模型轮次中的不同工具分别显示；同名工具在不同执行轮次也分别显示。参数和返回值可以在该调用下展开查看。

模型调用、`select_skill`、`read_skill`、`finish`、评分模型和其他协议事件仍然保留，但收进“内部协议详情”。这些事件用于审计和排查，不作为业务步骤重复展示，也不改变 R/A/J 评分。

事件不足时，界面只呈现证据边界：没有事件就没有业务步骤；只有技能选择没有读取不能声称技能已加载；工具开始后没有返回，在执行完成时显示“未确认”。业务工具返回不等于业务评分通过，最终评分仍由既有评分规则决定。

这套视图只改变展示层。试跑仍使用案例 fixture 或自由输入占位返回，正式运行仍保留完整事件；没有新增业务工具调用，也不改变内部工具协议。

验收覆盖：自动加载与缓存读取、历史独立读取、同一模型轮次多个工具、重复同名调用、fixture 错误、结束前后未确认状态、空事件和输入不可变性。

运行详情按版本、评测阶段、案例重复轮次归组，模型请求重试不新增分组。缺少版本字段的结束事件只有在同阶段、同轮次唯一匹配时才归入该执行；存在歧义时保留独立原始记录。

验证结果：隔离的暂存快照后端回归 490 项通过（1 条已有依赖弃用警告）；最终前端事件归并和流解析测试 23 项通过。真实浏览器使用本地慢速 demo 验证了试跑增量更新、展开状态保留、默认折叠内部协议，以及正式运行案例详情的分组与失败判定展示。未调用付费模型，未部署外部服务。
