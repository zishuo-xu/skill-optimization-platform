# Prompt 与 Skill 驱动的工具调用

## 目标与输入边界

业务输入只有 Prompt 和 Skill。工具名称、用途、参数和调用规则写在技能内容中，执行环境不再要求独立 Tool Schema。模型连接配置仍用于接入模型；案例 expected 与 fixtures 是评测数据，不是模型的工具说明，不得用于推导可用工具或向业务模型泄漏答案。

## 执行设计

- 保留 `select_skill`、`read_skill`、`finish` 等平台内部机制。
- 原生工具接口注册通用 `call_tool(name, arguments)`，模型从已加载的 Skill 获取业务名与参数。不额外调用模型解析或生成工具 Schema。
- 接收端校验封装的基本结构，禁止把内部工具包装成业务调用。业务事件和评分使用展开后的真实工具名；模型消息保持通用入口的调用关联。
- 文本接口使用既有结构化文本解析，业务名不依赖环境白名单。
- 业务执行仍由案例 fixture 模拟，不接真实外部服务。未匹配 fixture 明确失败，不制造成功结果。
- 页面继续突出加载子技能与调用工具，通用封装放在内部原始事件中。

## 一个案例内的 Agent loop

1. 用 Prompt、主 Skill、子技能索引、query/context 构造模型输入。expected 不参与消息构造，fixture 也不会作为工具定义注入。
2. 模型调用 select_skill；平台记录选中路线，并返回对应子技能正文。需要其他 reference 时才用 read_skill，已加载路径命中缓存，不重复注入正文。
3. 模型收到新正文后再生成业务调用。首次加载正文的同一批次若还含业务调用或 finish，这些后续操作暂不执行，返回提示要求下一轮重新生成；不会消耗 fixture 或记作已执行的业务动作。
4. 模型调用 call_tool(name, arguments)；平台记录真实业务名与参数，匹配案例 fixture，把返回交回模型。模型可以从返回提取下一步所需 ID，继续加载、调用或结束。
5. 每次模型请求前检查包含新增正文、调用参数及工具返回的上下文大小；运行中超限报告 context_overflow，不通过静默删掉历史破坏调用关联。请求/案例超时、调用步数和取消继续有效。
6. 结束后按真实事件组装路线、工具调用、返回与最终回复，交给评分器。默认缺少 finish 单独记协议状态；业务结果能否判定及严格模式见[评分规则](SCORING.md)。

缓存或预加载正文已经在模型上下文中时，不为读取同一文件额外增加等待轮次。平台能证明模型收到正文后有新的推理机会，不能证明模型内部一定使用了规则；仍需靠调用和参数评分验证效果。

页面展示的是“加载子技能 → 调用工具”的业务过程；select_skill/read_skill/call_tool/finish 封装与原始模型输出保留在详情。设计演进见[自动加载记录](SELECT_LOAD.md)与[执行约束记录](PROGRESSIVE_LOOP_2026-10-27.md)，当前操作见[使用指南](USER_GUIDE.md)。

## 评分与配置

移除环境字段、数据库新建表字段、模板、发布校验、预检、请求与评分中的独立 Tool Schema。工具调用的基本格式仍校验；工具名、调用顺序、参数值与案例 expected 比较。Skill 中规则是否遵守，需要对应测试案例覆盖，平台不宣称从任意 Markdown 自动证明参数合法性。

执行层不保留旧工具协议的兼容分支。启动时检测并移除旧数据库中的废弃字段，先备份再升级结构；不重置或删除项目和运行数据。

## 验收

1. 全新环境不含工具 Schema 仍可创建、发布、预检和试跑。
2. 模型请求只含通用业务入口和内部工具；expected/fixtures 不进入业务上下文。
3. 加载子技能后通过通用入口调用任意技能声明的业务工具，事件保留真实工具名、参数与返回。
4. 非法封装、缺失 fixture、错误参数与工具名仍有明确失败；正确结果按案例通过。
5. Python 回归、前端测试及本地浏览器执行环境/试跑流程验证通过。
