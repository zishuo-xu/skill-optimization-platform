# 选择技能时直接加载正文

原来的 native 工具链要求模型先调用 `select_skill`，再调用 `read_skill`。真实模型通常会因此产生额外的一轮“读取文件”请求，增加延迟和输入 token。

现在 `select_skill` 在记录路由事件后，直接读取 manifest 映射的文件并把正文返回给模型。运行时仍记录 `skill_selected` 和 `skill_read` 两类事件，所以路由评分和读取审计不变；业务工具调用仍由模型在看到技能正文后决定。

`read_skill` 保留用于读取其他参考文件，也兼容旧 Prompt。对已经自动加载过的相同路径，运行时使用当前案例内缓存，内部缓存复用正文并标记 `cached=true`，发给模型的是已加载确认，不重复注入正文或读取磁盘；显式重复调用仍保留为真实事件，便于诊断模型是否重复请求。

加载继续使用原有 manifest 映射、路径归一化、包目录边界、UTF-8 和单文件大小限制。上下文策略丢弃预加载内容时，不把它误认为模型已经收到正文。旧环境的 Prompt 不会被改写，运行时工具说明会覆盖“选中后必须再次读取同一路径”的旧提示。

这项优化只省掉一次读取型模型往返，不会把技能选择和业务工具调用强行合并；模型仍需在拿到技能正文后生成业务参数。选择与读取均为内部观测工具，不计入业务工具参数指标。新策略会带新的运行指纹，旧基线不会直接复用。

## 验证与边界

- 仅包含本次提交的隔离目录完整测试：490 passed，1 条既有 Starlette/httpx 弃用警告。
- 工作区技能加载与修图相关测试：159 passed，包含已有但未提交的修图示例改动的兼容检查。
- 脚本模型验证新流程 3 轮（选择、业务、结束），旧的显式读取流程 4 轮，两者业务评分一致；同批选择和读取、跨轮重复读取不会重复注入正文。
- 验证全量/部分预加载、超限回退、提示词中的伪预加载标记、文件大小与编码、目录外符号链接及未知技能。
- 隔离演示服务的真实浏览器试跑确认自动加载、文件路径、缓存命中与最终通过结果，截图 `output/playwright/select-load-trace.png`。
- 未调用用户的 DeepSeek 或其他付费模型；不保证模型一定省掉读取轮次，需更新服务后用实际模型确认。运行时仍接受旧模型的重复读取，保留真实调用记录。
